# 关系即函数

线是数据,关系是行为。**关系 = 函数**:输入若干线(与参数),输出派生的结构与值。
文档 = 全部线 + 全部关系构成的关系图;动画 = 关系图随时间的逐帧求值。

## 0. 规范表述(owner 给定,逐字收录)

> **集合本质是线和线的关系,只不过是预定义关系;关系就是函数;关系的参数就是集合的参数。**
>
> **模拟过程本质是线和线的关系。**
>
> **嵌套层、父子层本质是线与线的关系映射。**

由此:层/群组不是容器类型,而是**组织类预定义关系**;"层的不透明度/混合模式"
是该关系函数的参数;"帧率/色彩空间"等文档级参数是**根关系**的参数。

## 1. 预定义关系(标准关系库)

|---|---|---|---|

### 1.0.1 曲线复用与叠放(shape 关系,2026-11-13 owner 确立)

**一个曲线多个图形**:shape(填充域)是预定义关系,输入是**曲线/段引用**(带方向
flag,对应 Moho Shape 的 `edges {curve, segment, flag}`[^mohoproj-format])——同一条
曲线可被 N 个 shape 关系引用(改曲线一处,N 个形状同变);曲线自身仍可描边
(线级 `strokeOn`),Moho 的"一曲线双角色"由此回归。

**叠放位置**:
- shape 关系与线各带 **zOrder 参数**(Moho `shape_order` 本就可动画[^mohoproj-format])
  ⇒ **叠放顺序可打关键帧**(翻牌/遮挡反转);
- 改动方便的三层:命令 `rel.set zOrder`;AI 自然语言;舞台直接操纵(AI 现场生成
  深度滑杆——控制棒即线);语义命令 bringForward/sendBackward/toFront/toBack
  (= zOrder 确定性算术);
- **两层排序字典序合成**:层间=归属关系排序参数,层内=zOrder 参数;全局渲染序 =
  `(层序, zOrder)`;
- 同曲线的两个重叠填充域都渲染、按 zOrder 定先后(良定义);填充规则为 shape
  关系的参数(逻辑载荷)。

对照 Moho 语义的映射依据:
- 角约束:Bone `fConstraints`/`fMinConstraint`/`fMaxConstraint`[^m-bone];
- 智能骨骼(Action 拨盘驱动多通道查找表[^m-bone])→ 传导关系的特例并推广;
- 骨骼动力学(`fBoneDynamics` + 弹簧/阻尼/力参数族[^m-bone])→ 模拟关系的参数;
- Point 的 `parent` 绑骨索引[^mohoproj-format] → 绑定关系;
- `fileref{path,relativeTo}`[^mohoproj-format] → 外部资产引用。

### 1.2 交互关系(respond;2026-11-17 owner 确立)

全景调研(F11:感知→决策→响应是交互的最小模型;bool·number·trigger 输入三件套
在 Rive/Unity/Godot 独立复现)加 owner 的小白愿景(目标原话里就有"交互动画"),
使文件内交互成为本质能力。它完全落在"关系即函数"之内:

- **事件也是命令**:一次交互以 `event.fire {name, tick, target?, x?, y?}` 进入文档
  历史——重放的命令流包含行为,确定性(同文档+同流+同事件 → 逐字节同输出)
  对事件处理原样成立。事件是**不可逆事实**:`event.fire` 的逆命令是 `noop`
  (删除事件会改动其下游的一切);
- **事件词表 v1**:`tap` / `press` / `release` / `hoverIn` / `hoverOut`
  (指针相对目标线,引擎侧确定性命中测试=线段距离,与舞台同判据)、
  `overlap(lineB)`(当前 tick 的线段相交)、`timePoint(t)`(时刻到达);
- **守卫**:respond 关系可带参数条件 `{channel, op, value}`——带守卫的过渡,
  正是 Rive/Unity/Godot 的趋同结论(F11);
- **动作**(有序列表):`write {目标线+属性, 值 | 增量}`(**状态机 = 被
  带守卫的 respond 关系写入的离散参数**——离散值走 **step 插值 im=3**,
  即 Switch 层的等价物)与 `fire {name}`(连锁反应:一个事件触发另一个);
- **单写者纪律照旧**:respond 是*条件写者*——校验器拒绝动作目标(线+属性)
  已被任何无条件写者(track/oscillate/bind/…)认领的组合。合成模式:respond
  写专用控制参数,时间驱动的关系消费它;
- **纯播放器交互(N3)**:respond 关系在任何离线播放器中确定性求值,无 AI、
  无脚本(能力即数据,vision 规则 3)——求值语义见 §4;
- **v1 求值注记(随 C7 落地)**:命中测试与重叠检查使用**静止几何**(文档未动画的
  位置——确定且无环,这正是"点 X 写 X"合法的原因);重叠边沿在**折叠时刻**
  (已记录事件的 tick 与声明的 timePoint)采样,不是逐 tick——连续重叠监视是 v2 细化;
  多个带守卫的 respond 可以**共同合成一个参数**(状态机模式):fold 按
  (时刻,文档序)编排它们的写入,由首个认领者每帧恰好应用一次合成后的状态。

#### 手势时间线(2026-11-17 owner 确立——line-model §0 规范表述;**已落地(C8),2026-11-17**)

**交互事件是时间线**:一次手势的相位边沿(`hoverIn` / `press` / `release` /
`hoverOut`)是**手势线**上的关键帧——手势线是名为 `gesture/<target>` 的**步进轨道线
(im=3)**(无 target 的广播事件落 `gesture/pointer`),节点值=相位码
(0 移出 / 1 悬停 / 2 按下):

- **记录即物化**:`event.fire` 升级为**原子双写**——追加不可逆的 `MoEvent`
  (**结构不变**:单 tick、无时长、无相位字段)+ 在手势线上 upsert 相位键。键**只在
  相位变化时落**(同值 upsert 跳过)。线只随事件生长:校验器保留 `gesture/` 命名空间
  (用户线不得占用,任何关系不得写它),舞台拒绝拖动/删除其节点——事件不可逆,
  故其物化时间线**只读**;
- **相位语义遵循浏览器的 hover/click 之分**——线值跟踪*物理包含*(hover 语义),
  时长判别用*事件对*(click 语义:down 与 up 命中同一目标即完成,与路径无关;
  release 命中测试仍按半径):

  | 物理状态(半径内? × 按键?) | 浏览器对应 | 相位 | 落键时机 |
  |---|---|---|---|
  | 外 · 未按 | `pointerout` / 无 hover | 0 | 离开半径 |
  | 内 · 未按 | `pointerover` / `:hover` | 1 | 进入半径 |
  | 内 · 按下 | `pointerdown` | 2 | 半径内按下 |
  | 外 · 按下(按住划出) | 物理在外——`pointerout` 已发 | 0 | 离开半径(重入恢复 2) |
  | 内 · 抬起 | click 完成,仍悬停 | 1 | 半径内抬起 |
  | 外 · 抬起 | click **不**完成 | 0 | (已在 0——不落键) |

  不乱跑的常见情形下,按下段的长度**就是** `release.tick − press.tick`——时长是
  时间线上的长度,不是元数据字段;指针乱跑时两个量分化,恰如浏览器分化 hover
  与 click;
- **时长感知 respond**:release 类 respond 可带 `minHold` / `maxHold`(tick)——
  "长按/短按"是**手势线上的长度谓词**。fold 以确定性回看求值:在前缀中(按
  `(tick, seq)` 排序)为该 release 配对同 target 最近未配对的 press(per-target
  配对栈)——hold = `release.tick − press.tick`,对已记录事实的纯算术。`tap`
  保持现状(录制端合成的"按下且未拖动",`tap_jump` 冻结 demo 原样);概念上它是
  短且未移动的 press→release 对的速记;
- **读取保持无环**:v1 的守卫**只允许**读手势线——它派生自事件而非几何,
  "respond 不读线"的无环论证原样保留(事件 → 手势线 → 守卫是单向数据流)。
  把 track 守卫推广到任意轨道线会破坏该论证,推迟(§5);
- **渲染 = 只读参考泳道**:舞台把手势线画成时间轴上的淡泳道(会话覆盖层;
  tags `track` + `gesture`——离线渲染与场景快照按 `track` 线同样跳过),按下段的
  画出长度即时长。离线帧与冻结 PNG 哈希原样不动;拾取(命中测试)忽略手势线。

## 2. 动态关系(模拟)

owner 规范表述:**模拟过程本质是线和线的关系**——不是线之外的概念,只是关系
**由求解器逐帧算出**,而不是作者直接摆好:

- **弹簧/阻尼**:作用于骨骼线与骨骼线之间——"动态的约束";
- **重力/风**:场对线的作用,表达为线与(虚拟)线之间的关系;
- **碰撞***(已落地,B6)*:线与线的距离关系——sim 节点与碰撞体线段保持间隙半径,链可自分离,粒子以显式恢复系数从碰撞体弹开;
- **粒子**:发射器是一条线;每个粒子是一小段**有向线段**(位置+速度向量);
  吸引/排斥/附着也是线间关系。

求解器代码是 simulate 关系的**函数体**——在关系之内(owner 2026-11-17:"代码是关系里的,关系即函数";
非线边界已不再列入代码,见修订后的 [line-model.zh-CN.md](line-model.zh-CN.md) §4),
模拟的**结构**完全在线与线的关系里。确定性要求:随机种子必须显式化为参数,
同一文档同一输入 → 同一输出(CPU oracle 可验证)。

## 3. 自定义关系

用户/AI 定义的函数:函数体为逻辑载荷(表达式/脚本),参数即可驱动的参数(旧称"通道")。
这是 mo2d 可扩展性的唯一出口——**不新增内核原语,只新增关系**。
函数体在关系概念*之内*(owner 2026-11-17:"代码是关系里的,关系即函数"——
非线边界已不再列入代码,见修订后的 line-model §4)。

- AI 从自然语言生成:"让触手尖端跟随光标" → 生成一条自定义传导/模拟关系;
- 反向解释:选中任意关系,AI 可将其参数与行为翻译回自然语言;
- 自定义关系可被提升为预定义关系入库(标准库开放的扩展机制)。
- **表示边界**:自定义关系体经关系 IR 编译为 wasm 执行缓存(沙箱、派生数据、不计规范哈希);外部变量以
  **输入线**进入(宿主每帧写入);确定性=文档+录制输入重放。完整决议见
  [architecture.zh-CN.md](architecture.zh-CN.md) §2.1.1;组件列存储与 LineCore:§2.2。

## 4. 求值模型

- 关系构成 **DAG**:拓扑排序后逐层求值;
- **分层并行**:同层独立关系可并行;节点级参数采样是并行 map——
  与 GPU 执行模型同构(owner:线与线关系最大化利用 GPU,概念契合);
- **时间维度**:轨道关系先采样出本帧参数,再进入几何/动态求值;
  动态关系的状态随时间积分——**播放与 Scrub 的一致性策略已定(B6):种子重放**。
  每次求值都从 tick 0 以固定 240Hz 子步重新积分(254,016,000,000 ticks / 240 = 1,058,400,000
  精确整除),锚点节点逐子步从其驱动位置轨道采样。单次求值代价 O(tick/240 × 节点数)——有界,
  且回擦/重放/离线导出按构造逐字节一致;
- **事件维度(2026-11-17 确立,C7)**:求值是纯函数 **`f(doc, tick, 事件前缀)`**——
  截至 `tick` 的已记录 `event.fire` 前缀按 `(tick, seq)` 排序后**折叠**进参数状态
  (带守卫的 respond 关系执行其写入),折叠态再进入拓扑求值。折叠是确定的
  (同前缀 → 同状态)且廉价(O(事件数));空前缀恰好退化为时间驱动的
  `f(doc, tick)`——一切既有门与冻结哈希原样不动。Seek = 重放折叠
  (与种子重放同一哲学;若漫长事件史实测变慢,日后可加同类的逐 tick 检查点缓存);
  手势线相位键(C8)骑在事件 tick 上——**不新增**折叠时刻;带 `minHold`/`maxHold` 的
  release respond 给 fold 增加一次确定性回看(per-target press 配对,§1.2);
