# 愿景:AI 原生的 2D 矢量动画引擎

mo2d 是一个 **AI 原生的 2D 矢量动画引擎**:骨骼动画、矢量图形、位图网格变形、
时间轴——这些传统软件里的重型概念,归约为**线与线的关系**;而有了 AI,
标准 GUI 控件(工具栏/菜单/属性面板)不再是必需品——用户直接在舞台上
定义线及线间的联动关系即可。

## 1. 问题诊断

传统 2D 动画工具(Flash/Animate、Moho、AE、Toon Boom)的两个结构性困境:

**GUI 范式困境**
- 每个领域概念一组专属控件:工具栏、菜单、面板森林——功能组合爆炸,学习成本高;
- 刚性层树/组树是容器类型系统,概念冗余(层、组、元件、合成各有一套);
- AI 只能"模拟点击"操作它们——GUI 是给手的界面,不是给智能体的接口。

**异构数据困境**
- 位图、矢量、文本、骨骼各有各的数据结构与渲染路径;
- CPU 侧分支多,GPU 侧状态切换多,吞吐上不去。

## 2. AI 时代引擎的形态(定义)

**AI 时代的引擎不是特性集合,而是一门极小的语义语言 + 一台确定性运行时。
特性是 AI 的产出物,不是引擎的组成物。** 六个部件,缺一不可,也不再需要第七个:

1. **语义语言**(内核即语言):极小、正交、可组合的原语(mo2d:线/节点/段三级属性/关系/通道)。
   AI 的能力 = **组合的覆盖面**,不是 API 的枚举面——语言越小越稳,AI 越强
   (数千 API 是 AI 的坟墓,六个原语是 AI 的乐高);
2. **确定性运行时**:AI 编译,引擎执行;运行时永不调 AI;同输入同输出(字节级)。
   确定性是 AI 产出的**信任基座**——AI 每次生成可以不同,引擎每次执行必须相同;
3. **命令协议**:人、AI、引擎三方唯一的界面;可录制、可回放、可 diff。
   协议即产品——GUI 会过时,协议是资产;
4. **校验器**:schema + 确定性门(重放字节相等)+ 沙箱。利用**生成-验证不对称**:
   生成贵(AI 的事),验证便宜(引擎的事)——AI 时代工程安全的基石;
5. **性能机器**:均匀数据布局(SoA/实例化/损伤渲染)。概念统一的**双重红利**:
   语言小(AI 端好编译)+ 数据同构(GPU 端好吃满);
6. **可生成的视图**:GUI 从"产品"退化为"视图",控件即线,用后即弃。

| 维度 | 传统引擎 | AI 时代引擎 |
|---|---|---|
| 本体 | 特性集合(百万行代码) | 语义语言 + 确定性运行时 |
| 能力来源 | 人写特性,版本迭代 | AI 编译工件,能力即数据 |
| 界面 | GUI 给人,API 给程序员 | 命令协议给智能体;GUI 是生成的视图 |
| 学习成本 | 人学控件与概念 | AI 学语言(一次);人只表达意图 |
| 状态 | 不透明二进制 | 声明式、可 diff、可手改 |
| 质量保障 | 测试团队 | 生成-验证不对称 |
| 性能 | 异构特性各走各路 | 一种数据形状 ⇒ GPU 吞吐 |
| 进化 | 发版加特性 | 语言极少变;能力在 AI 层疯长 |

**底层经济学**:AI 时代,特性/界面/知识成为**充裕品**(AI 随手生成);
确定性/真值/性能/安全仍是**稀缺品**(AI 给不了)。**引擎持有稀缺,AI 生产充裕。**
"万物皆线"是使能决策:概念统一同时喂饱两端——AI 要小而稳的编译目标,
GPU 要同构的数据形状;一次统一,两头收红利。

## 3. 四条核心理念

1. **万物皆线**——骨骼、时间轴、矢量图形、位图网格、渐变、层,本质都是线的
   表示与控制([line-model.md](line-model.zh-CN.md));
2. **关系即函数**——集合/层/群组是预定义关系,模拟是动态关系,一切行为逻辑
   是线与线之间的关系([relations.md](relations.zh-CN.md));
3. **舞台即界面**——无标准工具栏/菜单;用户在舞台直接定义线与联动,
   AI 经命令协议完成一切操作([ai-interaction.md](ai-interaction.zh-CN.md));
4. **概念契合 GPU**——线+关系的统一模型与 GPU 执行模型同构:
   概念统一 ⇒ 数据同构 ⇒ GPU 吞吐最大化(owner:"线和线关系其实就可以最大化地利用 GPU,概念契合,提高性能")。

## 4. 概念契合硬件(四条论据)

| 环节 | 论据 |
|---|---|
| 渲染 | 节点通道 = SoA 数组 → 顶点属性/存储缓冲,一次上传全场景;变宽线→统一三角带,闭合线→填充细分;同构数据 = 极少 draw call、零状态切换 |
| 求值 | 关系 DAG 分层并行:层内独立关系并行,节点级通道采样是并行 map |
| 模拟 | 粒子=有向线段=实例化渲染+compute 积分;弹簧/约束=PBD 式并行求解 |
| 蒙皮/变形 | 绑定=顶点混合,GPU 顶点阶段的天然 workload |

## 5. 内核极简

**线(含节点与三级属性)+ 关系(函数)+ 通道(参数)+ 载荷**——四个原语承载全部领域概念;
非线的东西诚实留在边界外(采样场/符号逻辑/文档外状态/外部引用,见
[line-model.md](line-model.zh-CN.md) §4)。

## 6. AI 与引擎的分工(2026-11-11 owner 确立方向)

owner:"既然有了 AI,是不是可以将更多的能力交给 AI,而引擎只处理性能部分?"
方向成立,精确化:**引擎持有"性能 + 确定性 + 语义语言"三样,其余一切能力交给 AI。**

**三条铁律**:

1. **AI 编译,引擎执行**——AI 把意图编译成线/关系/通道/命令等确定性工件,引擎执行工件;
   AI 是编译器,不是运行时;
2. **创作时用 AI,播放时纯引擎**——建绑骨/做动画/写关系函数交给 AI(秒级延迟可忍);
   60fps 求值/渲染/模拟的每一帧是纯引擎数学,**运行时永不调 AI**;
3. **能力即数据**——AI 生成的能力(自动绑骨/口型同步/跟随光标)固化为文档里的关系与通道;
   文件离开 AI 也能打开、播放、导出(产品不被 AI 可用性绑架)。

| 留在引擎的(不止性能) | 交给 AI 的(能力层) |
|---|---|
| 确定性求值(CPU oracle、命令重放字节相等) | 自动绑骨、in-between、口型同步 |
| 语义语言(线/节点/段/关系/通道 = AI 的编译目标) | 运动合成、重定向、风格化笔触 |
| 热路径内置(蒙皮/模拟求解/轨道采样/渲染) | 控件生成(控件即线)、格式理解与转换 |
| 真值与校验(文档状态/schema/验收门) | 自然语言 → 命令翻译(既有) |
| 沙箱(AI 生成代码的安全执行) | 一切"怎么做"的知识 |

**一票否决**:运行时逐帧调 AI——确定性/性能/成本/可复现性全崩。
**架构落地**(见 [architecture.md](architecture.zh-CN.md) §2.1):预定义关系库收缩为
"热路径内核 + 语义锚点";AI 生成的关系函数体走受限 IR,入库前过确定性门。

## 7. 成功判据

1. 用户凭直觉(画线/拖节点/连线)+ 自然语言完成骨骼绑定动画,零菜单操作;
2. AI 通过命令协议完成**全部**操作(建线、建关系、打关键帧、导出),且命令流可回放复现;
3. 大规模场景(十万节点级)GPU 求值+渲染流畅;CPU oracle 与 GPU 输出一致(确定性);
4. AI 生成的能力固化后,**离线(无 AI)播放/导出**结果与在线一致。
