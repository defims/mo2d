# 架构草案

> 状态:**草案**。本文只定分层与原则,不做 crate 级设计;
> 技术栈为**倾向**而非决定(见 §5)。

## 1. 文档模型

**扁平线集合 + 关系图 + 参数表 + 载荷库 + 外部资产引用表。**

- 没有 vectorcraft 式的刚性 Node 树[^vectorcraft-arch]:层/群组只是**组织类预定义关系**,
  嵌套是关系的映射([relations.md](relations.zh-CN.md));
- 文档级参数(帧率、色彩空间、舞台尺寸)= **根关系**的参数;
- 数据骨架见 [line-model.md](line-model.zh-CN.md) §5。

与既有工程的关键差异:

| | vectorcraft / AniCraft | mo2d |
|---|---|---|
| 组织 | 刚性 Node 树(Layer/Group 容器类型) | 扁平线集合 + 关系图 |
| 领域概念 | 各自数据类型(Path/Bone/Text/…) | 全部投影为线 + 语义标签 + 关系 |
| 行为 | 特性代码各写各的 | 一切行为 = 关系(函数) |

## 2. 分层(L0–L4)

| 层 | 职责 | 说明 |
|---|---|---|
| L0 几何 | 线/节点求值、贝塞尔展平、命中测试 | 纯函数,无文档概念 |
| L1 文档 | 线集合、关系图、参数表(三级属性)、载荷库、外部引用 | 文档模型本体 |
| L2 求值引擎 | 关系 DAG 拓扑序求值、时间采样、动态积分 | 确定性核心;分层并行 |
| L3 渲染与计算 | CPU oracle 参考渲染器 + GPU(wgpu/WebGPU) | 变宽线三角带、闭合线填充细分、绑定顶点混合、compute 模拟/并行求值 |
| L4 交互 | 命令注册表、JSON 命令流、MCP server、AI 宿主 | 一切操作皆命令([ai-interaction.md](ai-interaction.zh-CN.md)) |

### 2.1 分工落地:热路径内核 + 关系 IR(vision §5 的实现面)

"更多能力交给 AI、引擎专注性能"的边界在工程上落地为三条:

1. **预定义关系库收缩**:引擎只保留**每帧热循环**的内置实现——蒙皮(绑定)、
   模拟求解(弹簧/粒子/碰撞)、轨道采样(插值)、渲染;其余"特性"不再写入引擎,
   改由 **AI 生成的自定义关系**承载(自动绑骨/口型同步/跟随等 = AI 在创作时
   编译出的关系网,不是引擎特性);
2. **关系 IR**:自定义关系的函数体不是解释执行的脚本,而是受限中间表示
   (沙箱 WASM 或表达式 IR):确定性可校验、可被引擎静态分析(依赖声明/纯度)、
   热路径可退化到内置实现;**AI 生成 → 过确定性门(命令重放字节相等)→ 才入库**,
   入库后即冻结为数据(重求值不再调 AI);
3. 运行时永不调 AI(一票否决,见 [vision.md](vision.zh-CN.md) §6);离线播放 = 纯引擎。

### 2.1.1 关系的表示边界——JSON 真值,wasm 作编译执行(2026-11-13/14 八轮压测决议)

**owner 的 JSX 类比**("像 JSX 的 XML 实际是函数调用——能否用 wasm 方法表示线关系、参数就是线?")方向对了一半。
JSX 本身是三层:源码(书写/评审/diff)→ 函数调用(代数)→ 元素树(运行时真值=纯数据)。JSX 从不在浏览器里跑,
跑的是编译产物,而真值是数据。决议照此定型:

1. **真值层 = `.mo2d` JSON**(线+关系+通道+body 源码)——AI 可读、可 diff、可 schema 校验、字节确定,永不替换;
2. **执行层 = 关系 IR → wasm**——自定义关系体编译进沙箱缓存:派生数据、可重生成、不计规范哈希、过期回退数据
   求值(与 preview/检查点同类);允许整图编译作执行缓存;浏览器加载走 `instantiateStreaming`;
3. **宿主词汇表 = 预定义关系库,每条声明读写集**——DAG 可见性所系(失效/并行依赖静态访问集;不透明 wasm
   调用图是黑盒)。

**格式为何不能是 wasm/WAST——伤单(含流式改判)**:

| # | 伤 | 说明 |
|---|---|---|
| 1 | AI 可读死亡(二进制;反编译得调用图,不得语义) | mo2d 第一原则 |
| 2 | 字节确定性失锚(同图编译出不同字节) | 冻结门需要规范源形态 |
| 3 | DAG 可见性死亡 → 失效/并行/GPU 批处理全面回退 | 除非声明效应——那又变回 IR |
| 4 | ABI 冰冻:每个旧文档都是按旧宿主词汇表编译的程序 | 对照未知键透传 |
| 5 | 校验变程序分析;"合法 WAST ≠ 合法文档"照样通过 | 校验器叠塔 |
| 6 | 编辑/合并/命令退化(改一个参数=重编译;CRDT/合并在二进制上) | |
| 7 | 渐进打开——**改判**:`instantiateStreaming` 确实赢"到全量";但 JSON 头+Range 赢"到首帧"(字段级原子;
     wasm 数据段整段到达)。两根轴不同;语义级渐进在 wasm-作-格式下仍缺 | |

**WAST 专项**:文本修复了伤 1 的一半(LLM 能读 WAT),但它仍是程序格式:无记录类型(字段退化成偏移量)、
大批几何退化为十六进制数据段(可读性再死一次)、浏览器执行的是 wasm 不是 WAST(每次加载都要编译,外加
wabt 工具链版本依赖)。

**"JSON 也要编译"——通行费不对称**:parse 是人人要付的入场费,差别在产物。JSON parse 产出**可寻址的真值
本身**;WAT 编译产出**还要再解释的程序**(挖"有哪些线、什么参数"得再做程序分析;格式校验+字段校验叠塔)。
成本也差 3–10 倍(类型检查+编码+实例化每次加载都付)。架构的答案:付一次——解析真值、派生执行缓存,
之后连 parse 都跳过。

**动画是活的/外界变量(第五轮)**:纯数据会撞墙——正确,但墙已预制进模型:**代码槽**(关系 `body` 在真值里
存源码文本)+ **输入线**(光标/音频/手柄=宿主每帧写入的线)+ 确定性升级为**文档+录制输入重放**(游戏
replay 配方)。

**zip:json 类比(第七轮)**:在**编码层**成立(wasm 之于 JSON,如 .gz 之于 .json——投递/计算包装),在
**内容层**断裂(解压后的 zip 还是你的可读文件;实例化的 wasm 是绑定宿主 ABI 的程序)。这个座位正是上面的
第 1↔2 层。

**一种语义,两种投影**:源码给人/AI/diff;字节给机器/沙箱/速度。可选的 s-expr 书写糖(KiCad 式带名节点、
version+generator 头、逐 key 容忍解析;注释只进糖层不进真值)编译到同一份 JSON 真值。

### 2.2 组件化存储与声明式调度(2026-11-22/23 决议——ECS 作内部投影)

**采纳**:ECS 组织**参数(存储)**与**关系调度**,不动语义层。关系图、命令协议、`.mo2d` 格式原样保留;
这是内部投影(又见"一种语义两种投影")。

- **组件列(SoA)**:宽度/颜色/zOrder/变换/速度各成列——还清 WASM 评估点名的胖 AoS `Node`(~96B/求值节点)
  旧账,GPU 上传天然 SoA;
- **关系 = 声明访问集 + 纯函数**:`relation bind { read: Bone.WorldXform, write: Node.Position }`——调度器
  从声明派生拓扑序、层内并行与失效(Bevy 式调度;relations.md §2.1 的"声明效应"即此);
- **变更检测替换反向依赖簿记**:每列版本计数,关系订阅列(`inval.rs` 行为不变、模型更简);
- **动态关系状态显式组件化**(速度/相位成列;检查点=列快照);
- **零依赖手写**:不引 bevy/flecs——10–100k 行级,排序 SoA 表+版本计数足够(AGENTS CPU-oracle 红线);
  确定性遍历(按实体 id 排序)、确定性合并序——全部过冻结门;
- **落地四步(每步过 47+ 测试与冻结门)**:①标量列先行(zOrder/width/opacity);②bind/track 改写为
  查询+函数模板;③inval.rs 重实现为变更检测;④胖 Node 退役。

**LineCore 万有组件束(2026-11-23,owner:"所有实体都有线相关属性,可被线相关函数处理")**:每个实体无一
例外——层(变换方框)、群组、骨骼、轨道、相机、渐变棒、网格族、文本轮廓——携带 `{nodes, 段属性, 域标签}`。
类型差异=**附加组件**(LayerParams…),不是类型继承。推论:

- **线函数普适**:命中测试、包围盒、空间索引、细分、导出、上传——只查 LineCore 的系统,对一切实体通用,
  零类型分派;
- **域标签是必需的精度**(舞台/时间/UV):轨道线在时间域、网格线在 UV 域;线函数按域匹配生效
  (命中测试是舞台域函数);
- **集合几何是派生的**:群组包围=成员派生线——惰性/缓存,不落存储,不计规范哈希;
- **AI 红利**:全场景一种几何语言——AI 问线问题,命中一切实体。

## 3. GPU 策略(专节)

owner:"线和线关系其实就可以最大化地利用 GPU,概念契合,提高性能。"

**核心论证:概念统一 ⇒ 数据同构 ⇒ GPU 吞吐最大化。**

1. **统一数据布局**:节点级属性 = SoA 数组(位置/宽度/颜色/值各一数组),
   直接映射顶点属性/存储缓冲,一次上传全场景;
2. **渲染**:变宽线 → 统一三角带展开;闭合线 → 填充细分;同构数据 =
   极少 draw call、零管线状态切换(对比传统软件位图/矢量/文本异构对象来回切换);
3. **求值**:关系 DAG 分层并行——同层独立关系并行,节点级参数采样是并行 map;
4. **模拟**:粒子 = 有向线段 = 实例化渲染 + compute 积分;弹簧/约束 = PBD 式并行求解;
5. **蒙皮/网格变形**:绑定 = 顶点混合,GPU 顶点阶段天然擅长。

**双轨纪律**(参照 maohou 的 CPU oracle + wgpu 双轨实践[^maohou-readme]):
CPU oracle 渲染器/求值器为**确定性真值源**,GPU 实现 = 加速器;两者输出必须一致
(逐像素/逐数值门)。MVP 期 CPU 起步、SoA 布局保 GPU 路(见 [mvp.md](mvp.zh-CN.md) §取舍)。

### 3.1 外部参照:BUI 的性能设计(2026-11-11 owner 询问后评估)

[BUI](https://github.com/ppmpreetham/BUI)(Blender UI 解耦出的 C 库,GPL-3.0)的
高性能设计与 mo2d 高度同构,五个**净室借鉴**点[^bui]:

1. **损伤渲染(damage rendering)**:变更只标脏自己的矩形(合并上限 24 个);
   无脏即睡(空闲 0% CPU);CPU 光栅按 64×32 tile 与上帧比较,只有损伤 tile 上屏——
   mo2d 编辑视口的呈现层照此;**求值侧的同构物 = 关系 DAG 的反向依赖失效**:
   参数变更只重算依赖子图(BUI 的 signal 单节点更新同理,"参数=信号");
2. **实例化 uber-shader**:每图元 = 单一 shader 的一个 128 字节 instance,
   整帧只有几个 instanced draw call——"万物皆线 ⇒ 数据同构 ⇒ 少 draw call"的
   **具体实现形态**:段/节点补丁 = instance,与 SoA 布局严丝合缝;
3. **双渲染器同像素**:CPU 光栅与 GPU shader 求值**同一公式**,奇偶校验门
   (172,800 像素仅 10 个差 >3/255)——双轨纪律的可行性证明与验收门形式(像素阈值奇偶校验);
4. **空闲零渲染 + 动画只在动时运行(按显示节拍)+ headless 虚拟时钟精确步进动画**——
   mo2d 确定性播放/回退测试的原语(headless 逐帧可复现);
5. **图像按绘制尺寸解码、线程外解码、内存预算缓存(默认 256 MiB)、离屏取消**——
   mo2d 媒体载荷(位图网格纹理)的管理参照。

**限制**:GPL-3.0(Blender 衍生代码)——只借鉴设计思想,**不引用实现**(避免许可证传染,
维持 MIT/Apache 倾向);GPU 后端仅 D3D11/GL3.3(无 Metal/WebGPU),实例化模式可平移到
wgpu/WebGPU 但代码不可;BUI 是控件级 UI 工具包,mo2d"舞台即界面"用不上其控件树/布局/CSS 主体。

### 3.2 流式渲染(2026-11-12,owner 问有什么好处)

流式渲染不是新特性,而是**把引擎已有的性质变现**:求值是纯函数 `tick → frame`,
即可暴露为**惰性帧流**(pull 式迭代器)。好处:

1. **体验**:首帧不必等(大工程渐进打开);**AI 迭代回路验证更便宜**(先流回受影响区的
   粗帧即可视觉确认——生成贵/验证便宜,正中分工铁律);导出变后台流(进度=已流出帧数,
   可暂停续跑——确定性保证续点一致);
2. **架构咬合**:与损伤渲染正交互补——损伤=**空间**增量(只重画脏区),流式=**时间**
   增量(只算下一帧)⇒ 时空增量渲染;播放/scrub/导出共用**同一条帧流**,只是消费速率
   不同;同一条流重放即同输出(确定性叙事强化);
3. **展示编辑一体的远端化**(§1.5):WebSocket 帧流让舞台跑浏览器、引擎留本地(或反
   之)——C6(wasm 舞台)的天然前置;MCP `screenshot` 推广为"从流中取一帧";
4. **工程**:导出内存 O(1)(4K×10 分钟=14,400 帧不积攒);纯函数帧使不同 tick 段可
   **零锁分区并行——唯动态关系(模拟积分)有状态依赖,该段只能顺序流或做检查点**;
   两种流各归其位:导出/录制走**像素流**,远端舞台走**显示列表流**(矢量绘制命令——
   还是线!带宽小一个量级,客户端可缩放)。

**格式影响:零改造(2026-11-13 owner 问)——三个既有选型恰好已预付**:
Tick 整数(任意帧独立重求值,scrub/seek 无漂移)、字节级确定性(断点续流=重放即一致)、
头部 JSON+尾部 BLOB 的 offset/length 布局(静态服务器 + HTTP Range 即可先取头、按需懒取
BLOB——渐进打开);工程目录形态(B7)再给文件粒度懒加载。唯一预留点:**模拟检查点**
——动态关系有帧间状态,长模拟文档的 seek 需从 0 积分;若实测变慢,加**可选 cache 节**
(按 tick 的状态快照):派生数据、可重生成、读端可忽略、**不计入规范哈希**(与 preview
同类),信封附加节而非文档模型改造,走版本化+未知键透传;现在不加,等性能数据说话。

**原理流程(2026-11-13 owner 要图)**:打开只解析 JSON 头(BLOB 惰性取)→
**帧流=惰性迭代器(pull 式)**:①轨道采样(轨道线二分找邻近关键帧→段级 interp 插值
→本帧参数)→ ②关系 DAG 拓扑序求值(失效检查:与上帧 diff,没变直接吐缓存帧;静态
关系直算;动态 sim 从检查点/0 积分)→ ③本帧几何 → ④渲染编码(实例流 SoA 打包,
双缓冲:编码帧 n+1 时 GPU 画帧 n)→ ⑤输出适配(像素流→导出/录制/AI 截帧;显示
列表流→远端舞台 WebSocket 下行)。**五原理**:拉取模型(不拉不算,空闲 0% CPU);
单一真值流(播放/scrub/导出/AI 验证/远端舞台喝同一条流);时空增量(时间×空间,
`inval.rs`+舞台渲染缓存即流式缓存层);双缓冲流水线;seek 两路(静态 O(1) 独立求值,
模拟从检查点积分)。远端变体=双向通道:命令流上行、帧流下行。

落位:Phase A 不动;归 **B2 × C6 交界**(B2 出空间增量,C6 出传输通道,流式是"时间
增量"这第三块拼图)。

### 3.3 事件驱动求值(2026-11-17,owner 确立——C7 交互切片)

全景调研的交互最小模型(`姿势 = f(参数)`,`参数 = g(输入, 时间, 物理)`;landscape F11)
加 owner 的小白愿景,使文件内交互成为本质能力。引擎的回答保持拉取模型不动:

- **求值扩为纯函数 `f(doc, tick, 事件前缀)`**——截至 `tick` 的已记录 `event.fire`
  命令前缀按 `(tick, seq)` 排序后**折叠**进参数状态(带守卫的 respond 关系执行其
  写入),再照旧进入拓扑求值([relations.zh-CN.md](relations.zh-CN.md) §4 事件维度、§1.2)。
  空前缀恰好退化为原先的 `f(doc, tick)`——**一切既有门与冻结哈希原样不动**;
- **事件也是命令**:`event.fire` 进注册表与命令历史——重放包含行为,其余一切照常
  可撤销,事件本身是不可逆事实(逆命令 = `noop`);
- **状态机不是新概念**:离散参数(step 插值,im=3——Moho `INTERP_STEP` 码)+
  带守卫的 respond 关系;监听器=目标线上的 respond 关系;命中测试(tap/press/hover:
  线段距离;overlap:线段相交)是引擎侧确定性几何,对**静止几何**求值
  (v1 注记:重叠边沿在折叠时刻采样——连续监视是 v2 细化);
- **单写者纪律照旧**:respond 关系是*条件写者*;其动作目标(线+属性)不得被任何
  无条件写者认领(校验器强制);合成模式="respond 写专用控制参数,时间驱动的关系消费它";
- **Seek** = 重放事件折叠(O(事件数),廉价;与种子重放同一哲学——若漫长事件史实测
  变慢,日后可加与 §3.2 sim 缓存同类的逐 tick 检查点缓存,同样不计入规范哈希);
- **舞台**:tap 手势加入 draw/drag/connect/scrub 成为**第五操作**(MVP D8 修订,
  owner 2026-11-17 批准——仍零按钮、零面板,每个手势都是命令)。纯离线播放器确定性
  求值 respond 关系 ⇒ N3 门("点它就跳",无 AI 无代码)经同一命令流回放;
- **手势时间线在命令层物化(C8,owner 2026-11-17 确立——line-model §0 规范表述、
  relations §1.2、mvp D10)**:`event.fire` 升级为**原子双写**——追加 `MoEvent`
  (结构不变)+ 在 `gesture/<target>` 上 upsert 相位键(广播事件落
  `gesture/pointer`),即一条**只随事件生长**的步进(im=3)轨道线(只读:
  `gesture/` 命名空间保留、舞台拒绝编辑其节点、拾取忽略它)。fold 把手势线键当作
  普通文档数据——键骑在事件 tick 上,**不新增折叠时刻**;fold 的唯一扩展是 hold
  回看(带 `minHold`/`maxHold` 的 release respond 在前缀中配对同 target 最近未配对
  的 press——对已记录事实的确定性算术)。渲染:舞台把手势线画成**时间轴上的只读
  参考泳道**(会话覆盖层,tags `track` + `gesture`);离线渲染按 `track` 线的同一
  惯例跳过它们(Tick 节点"永不渲染"的同款约定)⇒ **冻结 PNG 哈希原样不动**,
  `MoEvent` 仍是单 tick 不可逆事实。

## 4. 存储格式原则

**细则与信封草案见 [file-format.md](file-format.zh-CN.md)**(2026-11-11 立;本节保留原则摘要):

- JSON 信封 + 可选尾部 BLOB 区(大载荷不 base64);**.mo2d 单文件即交付包**(交付即工程);
  可选工程目录形态(解包:document.mo2d.json + assets/)与包等价;
- **时间 = Tick 裸整数**(每秒 254,016,000,000,maop 实证),fps 只是显示参数;
- **字节级确定性**:稳定字段序、正文无时间戳、原子写;
- **未知键透传 + 扩展命名空间**(glTF 式;承诺不剥外来键——Moho 教训);
- **命令历史内嵌但分离**:document 为真值,history 仅审计/回放;
- **资产外置引用**:file:// + 相对基准;preview 可选、不计入规范哈希;
- JSON Schema + 校验器;FORMAT_VERSION 逐版读端迁移(vectorcraft/AniCraft 实践);
- 扩展名:`.mo2d`(待定)。
