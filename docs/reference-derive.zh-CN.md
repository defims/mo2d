# 可参考对象与派生链

2026-11-22/23 owner 会话的决议集合(视频作参考、白模 rig 管线、zip/json 家族之问、
填充类型派生、ECS 追问)。全部落在既有原语内——**零新概念**:线、关系、轨道、媒体载荷。

## 0. 规范表述(owner 给定,逐字收录)

> **视频和参考球(人物头部转面参考用)类似,都是可参考对象之一;视频层,有自己的时间线。**
>
> **可参考的不止视频和 3d 球体,任意矢量图形本身也可以作为参考继续派生。**
>
> **画条封闭线,可以创建图形;图形填充可以纯色,可以渐变,也可以视频,以后可以扩展其他——类似 html 的 video、img 标签。填充渐变就会派生出渐变控制线,视频会派生出时间线。**
>
> **由于 mo2d 是查改一体,派生实际就是 ecs 里处理 component 的方法处理的。**

(参考球属 3D 会话,D11——3D 球体作为头部转面参考,以 2D 侧影轮廓线/转面表表示。
视频层以时间性媒体成员的身份加入该家族。)

## 1. 参考是角色,不是类型

数据层里,内容与参考是同一个东西——线+关系。区别只在**角色标注**:任意实体都可以
充当——

- 最终成品(被渲染),
- 参考(垫底/隐藏,供人与 AI 视觉对照),
- 派生源(作为派生关系的输入,产出新内容),

且派生链继续:视频 → 白模 → 风格化角色 → 换装变体。每一环都是一条派生关系;每个
中间体都可以成为下一环的参考。链是有向无环的(既有 DAG 规则强制);关系图之上的
**血统视图**让"什么从什么派生"可见(零新存储——inputs/outputs 已经记录)。

**家族成员**:3D 参考球(D11:表示为侧影轮廓线/转面表)、视频层(时间性媒体)、
任意矢量图形(派生源)、白模(被派生的参考)、导入的 SVG(派生源)。

## 2. 视频层——自带时间线的可参考对象

```
视频层 = 帧框线(4 节点闭合线;摆放/缩放)
        + 视频载荷(媒体场;外部引用/BLOB)
        + 时间映射轨道(文档 Tick → 视频 Tick;可动画)
```

- **自己的时间线**:映射本身是作用于时间的轨道关系——慢放/倒放/循环/偏移都是映射
  上的关键帧(Moho ImageLayer、AE time-remap、Remotion `<Sequence>` 先例;位图网格
  单四边形是同一锚定形状,只是纹理会动);
- **参考是活的**:垫底的当前帧跟随文档时间轴——AI 视觉采样与用户对稿描线看到的
  永远是"此刻的参考帧";映射轨道可放慢 2× 以拆解快速动作(动画师标准手法),
  也可循环;
- 载荷是媒体场(非线边界第一类);语义(部件/关节)永远不解析进格式——它们是
  建立在其上的派生关系(§3)。

## 3. 白模管线——一条 AI 在环的派生关系

参考视频 → 白模 rig 的转换表达为**一条派生关系**,输入是视频层(AI 视觉在测量段
参与,脚本裁决;方法论照 h2o——见 [h2o-decompose-survey.zh-CN.md](h2o-decompose-survey.zh-CN.md)):

1. **部件分割**:滑窗仿射拟合;运动一致性相同的像素聚类为部件(头/躯干/大臂/小臂/…)
   ——剪纸式刚体部件;
2. **部件重建**:每部件取一个干净帧 → 剪影 → 描摹为 mo2d 闭合线+纯色填充(白模;
   满足禁原片像素规则);
3. **关节推断(数学核心)**:相邻部件 B 相对父部件 A 的变换序列 `T_rel(t) = A(t)⁻¹·B(t)`
   是绕关节的旋转——**关节就是不动点**,两个时刻的不动点求交,亚像素解出;部件层级
   由相对运动复杂度推出;
4. **骨架 = 过关节的折线**(共享节点——owner 规范形态);**bind 关系**把部件轮廓
   节点绑到所属骨线;
5. **运动迁移**:每部件仿射序列分解为所属骨骼的角度/位置分量 → 带.Tick 关键帧的
   轨道线(h2o 测量表就是关键帧表)。

**边界诚实**(采用 h2o 的 L1/L2/L3):刚体剪纸部件 = 🟢 全管线直通;透视翻转
(3D 转头)= 🟡——白模假设破坏 → **转面表**:每个朝向一套白模,String 轨道切换
(switch 轨道语义);柔性形变(布料/头发)= 刚体管线 🔴 → B6 模拟尾巴或 switch
多姿态;遮挡处形状 = AI 补全高亮标"推断"+用户确认。

## 4. 派生链——活链接 vs 快照

从参考派生形成链(视频→白模→风格化→变体)。唯一新增设计点,**派生关系的参数**:

| 模式 | 行为 | 适用 |
|---|---|---|
| **活链接** | 参考更新传播进派生物 | 白模跟随参考视频(改参考节奏,对稿随动) |
| **快照** | 派生时刻冻结,此后独立 | 换装变体(改变体不得反向污染参考) |

先例:GPv3 drawing 实例化、Rive artboard 引用。环仍禁止(DAG 规则)。关系图的
血统视图(§4)呈现链条。

## 5. 填充类型 = 组件对账(查改一体)

**画条封闭线 → 一个图形;图形的填充声明类型——机械自动派生**,如同 HTML 的
`video`/`img` 标签:

| 填充 kind | 派生 | HTML 类比 | 状态 |
|---|---|---|---|
| `solid` | 仅填充色属性 | `background-color` | 已落地 |
| `gradient` | **渐变控制棒线**(节点=色标)+ 渐变关系 | `linear-gradient()` | 棒+关系已落地;UX 命令为新 |
| `video` | **视频层**(§2)+ 填充采样关系(形状裁剪视频) | `<video>` | 组件齐备(B5+视频层);组装待做 |
| `image` | 图像资产 + UV 锚定(位图网格单四边形) | `<img>` | B5 |
| `pattern` / `shader` / `audio-reactive` | 图案线阵列 / 自定义关系体 / 输入线驱动 | — | 远期注册表条目 |

**由于 mo2d 是查改一体,派生不是特殊管线——而是一个处理组件的对账系统**
(owner 的表述):

```
Shape 实体:  FillComponent { kind, ref: 派生物实体 id, params }
DeriveSystem(kind): FillComponent 变更 → 确保派生物存在且链接(缺则建,断则修)
```

**所有权两分(唯一的大坑,一条规则堵死)**:

- 派生系统只管**存在与链接**(幂等对账);
- **派生物的值归用户**(控制棒节点、视频 src、时间映射关键帧)——对账绝不覆盖。

这是 React 的 props/state 之分。收益:`fill.set` 缩为"设 FillComponent"(其余全是
系统反应);撤销/重做照旧(设组件流);确定性保留(给定组件状态,对账确定);
扩展=每种 kind 注册一个 system。

## 6. 路线图落位

- **C9 参考层与白模派生**(roadmap):视频层 + §3 派生关系 + 活链接/快照;依赖 B5
  (媒体载荷)与已落地的 bind/track;
- 填充类型注册表:`gradient` 组装是已落地 B3 之上的薄 UX 命令;`video`/`image` 填充
  随 C9/B5 落地。
