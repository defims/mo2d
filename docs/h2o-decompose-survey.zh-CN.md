# 调研:h2o-video-decompose

一个 Claude skill:拆解用户提供的视频(镜头、切点、逐帧运动、字体、颜色、声画对齐),
让 AI 能**以可编辑工程 1:1 重建**(Remotion / AE / CSS / **Canvas** / Blender / 3DGS)。
源码级调研:本地克隆 + 三个并行深读覆盖全部 12.7k 行。

## 1. 它是什么——关键发现

它是一套**测量 + 派工 + 验收**系统。**不附带任何 canvas2d/JS 模板、脚手架或代码生成
约定**("Canvas" 只作为路由标签出现——JS 由分段子代理从零编写)。1:1 的可能性不来自
模板,而来自**测量数据 + 硬合同 + 量化验收门**:

> 把视频测量成逐帧数字 → 子代理依据数字在合同约束下重建(坐标链/时间模型/禁原片
> 像素)→ 四道门裁决导出 → 返修直到字节级一致证据说通过。

这是"AI 编译、门禁裁决"——与 mo2d 的分工铁律同一哲学,也是 ai-era 审计中 R5
(agent 写声明式源+确定性渲染)的行业级实证。

## 2. 管线(九阶段)

1. **安装自检**:Python 3.12 venv + ffmpeg(libx264);烟雾测试渲染并扫描合成片段;
2. **scan**:ffprobe 逐帧 PTS 索引(首帧=零;区间左闭右开)→ 180px 解码 → 灰度 MAE
   切点候选 → 故事板 + lookdev 关键帧;
3. **场景范式分类**(每镜头):直方图前两箱占比 > 0.68 + 单应 holdout p95 ≤ 2.75px →
   `2D_PLANAR_UI_MOTION`(→ Remotion/AE/**Canvas**);视差 P85/P20 > 1.35 →
   `3D_BLENDER_SCENE`;双高 → `HYBRID_2D_OVER_3D`;
4. **能力分级**:🟢 L1(2D UI/动效——全量复刻)/ 🟡 L2(需验证资产)/ 🔴 L3(超边界
   —— notably **传统手绘逐帧动画诚实标 🔴**);逐镜头分级,"不一刀切拒接整条视频";
5. **重点效果清单**:逐镜列出最影响观感的变化,各带可观察通过条件(成为强制验收项);
6. **开工问卷**(AskUserQuestion 批量:路线/档位/子代理模型…)+ 分工确认表;
7. **measure**(核心):逐镜头计划(参考帧、桥接帧、稳定/排除区、锚点、关键帧化区域盒)
   → 逐帧单应 + 轨迹 + 边缘宽度(见 §3);
8. **分段重建+返修**:子代理编写可编辑分段(2D 即 canvas2d/JS 工程)——**禁原片像素
   规则**("禁止把原片片段、静帧、截图…作为底图、纹理或其他可见层");第 0 版免费,
   每段 ≥ 1 轮返修;
9. **总装+整片验收**:合并、PTS 同步检查、可编辑性证明(改一项关键元素→重渲染→确认)、
   最终导出跑 `effects` + `continuity`;分段通过不替代整片结论。

主从 Agent 结构**对复刻强制**(总负责人只做扫查/分级/派工/总装;精细档每段负责人
≤ 2 秒;宿主不能建子代理 → 停工说明,绝不降级单 Agent)。

## 3. 测量层(全经典 CV——零深度学习)

- **稀疏 LK 光流**(winSize 29×29,3 层)+ **双向门控**——反向跟踪须回到 1.15px 内,
  否则弃点;
- **NCC 模板匹配**:DoG 归一化 25×25 模板在 53×53 窗搜索,得分 ≥ 0.64 带 0.045 唯一性
  边距,抛物线亚像素细化;
- **分级模型拟合+空间留出**:相似→仿射→单应(USAC_MAGSAC,2.8px),复杂度惩罚选简
  模型;34×31 网格留出格;仅当 holdout_p95_px ≤ 2.75 才 `validated`;
- **ESF 边宽模板库**:288 个 erf 模板(32 σ × 9 平移 × 57 采样);宽度 = 2.563σ
  (10–90% 过渡宽度),振幅/平台/残差有效性门;
- **场景分类器**:16 箱直方图前两箱 > 0.68 + 平坦梯度 > 0.58(+2.5 向 2D)vs 明暗
  渐变/消失点/视差(+1.8–2.0 向 3D);
- 输出:`measurements.json` 逐帧 `{geometry.H, status, holdout_p95_px, metrics
  (锚点/跨度/角度), zones (边宽统计), independent_checks}` + CSV 镜像 + 标注叠加 +
  轨迹曲线。

**数据合同即交付物**:逐帧 H(相机/平面运动)、逐层轨迹(端点/轮廓点/部件角度)、
分区边缘宽度、色板中位色、字体 IoU、声画事件表——画布/JS 作者不看原片像素也能重画
的全部信息。

## 4. canvas2d+js 合同(三种图层 + 一条变换链)

- **图层三分类**(由观察判定):(a) 相机承载的静态平面——参考帧上画一次,每帧套 H;
  (b) 独立运动元素——去运镜后拟合局部轨迹;(c) 画幅固定元素(HUD/打字/字幕)——
  直接画幅坐标。判定法:在画幅坐标与页面参考坐标各跟踪一遍,**谁更稳属谁**;
- **变换链**(逐字引用):"若 A 把工程图层坐标映射到测量参考帧,H_f 把测量参考帧映射
  到当前分析帧,S 把分析像素映射到输出画幅,则复刻投影为 S · H_f · A,最后除以齐次
  坐标";
- **时间模型**:恒定帧率→按源帧号对齐;可变帧率→首帧 PTS 为零,PTS 差绑定渲染时间;
  2 秒测量窗+重叠已验证锚点;
- **无命名缓动**:轨迹按源帧号/PTS 对齐的逐帧实测值存储,记录相位(起动/峰值/停顿/
  层间延迟/回弹/趋稳);量值不可信就留空只给顺序;
- **禁原片像素**:实测构图/颜色/轨迹/时序可写入独立重建图层——仅此而已;
- 字体:对候选做**多对比度阈值二值轮廓 IoU**(逐字墨迹框对齐归一化);颜色:稳定区
  中位色(记源帧+矩形+色空间);软边:边缘法向亮度剖面。

## 5. 验收环路——四道正交门

所有门共用退出码契约 **0=通过 / 2=需返修 / 3=待复核**,及反作弊机制:**review_id** =
(脚本+参考+复刻+计划)的 SHA-256;`--previous` 须同参考同计划但**复刻哈希不同**
("相同导出不能证明已修复");人工决定须附证据;"缺测不能通过人工结论覆盖";只有
**本次导出**的报告算数。

1. **measure(位置/时序)**:复刻件重跑测量;H/轨迹与参考表对比;
2. **lookdiff(外观)**:20 项局部外观指标,各带分辨率地板(`edge_width` 0.72px、
   `period` 1.1px、Lab `color_a/b` 7、`attachment` 0.24…)+ 比例阈值 + 噪声地板;发现
   须**跨帧符号一致 ≥ 0.75**;**编解码器弃权**——重编码对照实验能复现残差时判
   `insufficient`,不冤枉材质;盲测:留出项目前三定位 16/16、误报 3/16;
3. **effects(逐效果项)**:7 模式(motion / perspective / trail / focus / visibility /
   **impact(声画:5ms RMS 起音 vs 画面冲击)** / manual);每模式专属算法(透视=
   SIFT+单应+差分透视缩短向量;拖影=四轴高斯能量比;景深=逐层 10–90% 宽度…);
4. **continuity(整片导出)**:**双向 DIS 稠密光流**——往返误差 > 2px = mismatch;
   12 类缺陷判定(场景/图层突变、亮度阶跃、运镜急停、往返抖动、重复帧、原片事件
   缺失…),各带精确阈值;证据=1× 并排 + 4× 慢放片段。

3D 路线另有:`compare --strict`(19 项 lookdev 门控 + 光度/材质阈值 + SSIM ≥ 0.72 /
Edge-IoU ≥ 0.55)与 `audit-blend --strict`(无头 .blend 审计,执行"不降速妥协"渲染
政策)。

## 6. 曲线绘制之问——视觉/测量分工

**曲线怎么拿到参数?**不做矢量化——全仓没有任何 tracing。参数管线是:**AI 选判别量**
(线端点、轮廓点、部件角度)→ 写进测量计划(`independent_points`)→ **脚本逐帧跟踪**
(光流+NCC,亚像素)→ **canvas 作者受实测轨迹约束作画**(曲线表示法任意,过像素门
即可)。

推论:
- 静止帧的矢量由 **AI 看参考帧创作**(语义判断:"这是圆角矩形/圆/自由曲线"),量出
  的盒子/颜色/宽度是硬约束;
- 自由曲线 = **线上采样点 → 穿点拟合路径(Catmull-Rom→贝塞尔机械转换)→ 像素门
  验证**(偏差超阈值的段落加密采样重拟合);
- 对视觉模型的精度要求刻意压低("描述这张截图"级别):**视觉提议、测量裁决、像素门
  审判**——模型质量影响返修轮数,不影响质量上限(直到 🔴 边界:经典 CV 本身失效的
  非刚体乱动/手绘帧)。

## 7. mo2d 交叉启示

1. 测量 JSON(逐帧 H + 轨迹)**几乎就是 mo2d 轨道线的输入形态**——每条
   `independent_point` 轨迹 = 一条轨道线带 Tick 关键帧节点;"视频→白模 rig"成为一条
   派生关系,h2o 管线是其测量段(见 [reference-derive.zh-CN.md](reference-derive.zh-CN.md));
2. **该 skill 证明了的缺口**:每段从零重写 canvas 代码——无引擎语义(无 Tick 真值/
   无关系复用/无确定性缓存)。mo2d 正是这个缺口:测量数据可编译进 mo2d 线+关系+轨道;
3. **吸收进 roadmap C 验收设计**:四门结构(位置时序+外观+逐效果+整片导出)、退出码
   契约、review_id 反作弊、编解码弃权、盲测协议(留出合成病例从不参与调参);
4. **采用 L1/L2/L3 诚实边界措辞**(逐镜头分级;"手绘逐帧=边界外"是明示不是隐藏);
5. 主从派工纪律(段≤2 秒/返修归原负责人)映射 mo2d 自身的 agent 工作流。
